- Add `67js/addons/crowd-skinning` (issue #323): `createCrowdRig`, `bakeCrowdPalette` and `createCrowdParts` bake a character's clip into a joint-matrix texture once and draw every instance of it as one instanced batch per material, each instance sampling its own clip time, so draw calls stop growing with the number of people. Instances are culled by a bound that covers the whole clip, and `createCrowdLods` gives coarser levels skinned with the same joints. The renderer gains small hooks for it (a `crowd` part field, a `crowdPacked` geometry attribute, a `crowdEnabled` shader uniform); skinned parts without `crowd` behave as before.
- Add recipe crowds, a lower pose rate for far instances, and maps and morph targets on crowd parts (part of #323). An asset placement with `crowd: { clip, count, seed, layout, spacing, ... }` fills a group node with up to 1000 walking copies of one catalog character in one batch per material, and `scene_inspect` lists it under `assets` with `kind: "crowd"`. `farDistance` and `farRate` (recipe) or `farPose` and `setTimes(times, eye)` (addon) make far instances hold each pose for `1 / rate` seconds without breaking seek equals play. `createCrowdRig` keeps UVs so materials with maps draw on a crowd, and `{ morphs: true }` keeps morph targets on their own part. The crowd shader now reads its joints and weights packed in the colour attribute, which frees the UV attribute and makes the core bundle slightly smaller. `docs/retarget.md` has the measured RTX 3060 numbers: 500 `RobotExpressive` instances at a median 5.75 ms (8.27 ms in a later run on a shared card) with 7 draw calls.
