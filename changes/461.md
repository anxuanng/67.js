- Decode EXT_meshopt_compression inside `loadGltf` and `parseGltf` (closes #461). Attribute, triangle and index modes with the NONE, OCTAHEDRAL, QUATERNION and EXPONENTIAL filters decode with no `options.decoders.meshopt`, so gltfpack and Sketchfab files, `public/wall-e.glb` and the three showcase worlds (both parts each) open, and so do they in the MCP asset catalog and `scene_create_asset`. The decoder is meshoptimizer's WebAssembly build that three.js already ships, in a chunk (`src/gltf-meshopt.js`) that only a file with a compressed buffer view loads: entry:core, lit-box, gltf-box and agent-scene do not grow (gltf-box -31 B gzip). The fallback buffer is never read and does not count against `maxBytes`, so it may be absent or an unreachable `uri`. A view that fails to decode throws `EXT_meshopt_compression could not decode a buffer view` with its mode and filter. `options.decoders.meshopt` still replaces the built-in decoder. The showcase page no longer imports a decoder itself.
