- **Breaking:** glTF limit errors are now one `RangeError` that names every limit the file goes over, the measured value and the value that fits, for example `glTF over its limits: vertices 9120000, over maxVertices 8000000. Fix: pass { maxVertices: 9120000 }.` (issue #458). Code that matched the old messages (`glTF exceeds maxBytes.`, `Texture image exceeds maxTextureImagePixels before decoding.`) has to match the option name instead.
- Raise the `loadGltf` and `parseGltf` defaults so one large exported scene loads without options: `maxBytes` 256 MiB (was 32 MiB), `maxVertices` 8,000,000 (was 2,000,000), `maxParts` and `maxInstances` 65,536 (were 20,000 and 4,096), `maxResources` 256 (was 64), `maxTextureImagePixels` 8192 x 8192 (was 4096 x 4096). `maxTexturePixels` and `maxJoints` keep their values. `GLTF_CAPABILITIES.limits` lists the defaults. The port showcase, whose 6144 x 3072 texture went over the old image ceiling, now opens through MCP `scene_create_asset`.
